## 0. Термины

| Термин | Значение |
|---|---|
| Авторитетное состояние | то, из чего следующий запуск обязан исходить и что нельзя заменить ничем другим |
| Временное состояние | живёт не дольше одного запуска; его потеря не меняет авторитетного состояния |
| Декларативный вход (р2) | файл в main, который описывает, что делать, но не хранит ход выполнения: `TASKS.json` |
| Доказательство | запись о проверке, привязанная к точному коммиту и run id; доказательство само по себе не даёт полномочий |
| Принятие | переход, после которого изменение становится частью авторитетного состояния |

## 1. Что где хранится

| Данные | Этап 1 | Этап 2 (отложен, §3) |
|---|---|---|
| Код ядра, тесты, workflow, схема очереди, миграции, политики | main | main |
| `TASKS.json` (р2) | main, **декларативный вход** | main, декларативный вход |
| `TASK_QUEUE.json` (р2) | **только временный**: создаётся в начале запуска из `TASKS.json` и обнаружения; **в main не хранится и из main не читается** | ветка `state/queue` |
| Записи проверок | во временной очереди; выгружаются как артефакт-доказательство | коммиты `state/queue` |
| Аренды | временные | `state/queue`, действуют до `LEASE_TTL` |
| Логи, отчёты, артефакты CI | доказательства, не состояние | то же |
| Принятые изменения кода | только PR и слияние владельцем | то же |

**Правило для обоих этапов.** Артефакт Actions никогда не является авторитетным состоянием. Его можно читать как доказательство запуска, но восстанавливать из него очередь нельзя.

(р2) **Однозначность этапа 1.** Если `TASK_QUEUE.json` окажется закоммиченным в main, это нарушение контракта. Запуск этапа 1 его не читает, а будущая проверка CI должна такой файл отклонять. Состояние выполнения существует только внутри одного запуска.

## 2. Этап 1: временное состояние

**Гарантии:**
1. Запуск начинает с пустой очереди и наполняет её из `TASKS.json` и обнаружения на SHA, которым запущен. SHA и run id пишутся в результат.
2. Один запуск обрабатывает одну задачу (`run_cycle`). Аренды и `LEASE_TTL` защищают от двух исполнителей внутри запуска.
3. В конце очередь и доказательства выгружаются как артефакт-доказательство. Следующий запуск их **не читает**.
4. Изменение очереди становится постоянным только через PR в main. На этапе 1 так не делается: очередь не хранится вовсе.

**Явно не заявляется:** автономное продолжение между запусками, накопление истории, «непрерывный цикл».

**Повтор после сбоя.** Упавший запуск ничего не меняет в авторитетном состоянии. Повторный запуск начинает с того же main.
(р2) Это гарантирует отсутствие дублей **внутри ядра**. Будущим обработчикам с внешними эффектами (PR, комментарии, вызовы API) понадобятся свои ключи идемпотентности и явная граница эффекта. Пока такого обработчика нет, это требование к первому из них.

**Отключение:** `--disable-file` и переменная `AUTOPOIESIS_CYCLE_DISABLED` для workflow. `DISABLED` (код 0) отличается от `RECOVERY_REQUIRED` (код 3).

## 3. Этап 2: ветка операционного состояния — ОТЛОЖЕН (р2)

**Условие включения:**
- G3 реализован и проверен;
- есть хотя бы один содержательный (не шаблонный) обработчик;
- владелец отдельно решил выдать права `contents: write` и задать ruleset для `state/queue`.

До этого раздел остаётся проектом, а не реализацией.

**Устройство (проект):**
- `state/queue` содержит только `TASK_QUEUE.json` и `STATE_MANIFEST.json`;
- писатель единственный: job `persist-state` с `contents: write`; обработчик работает в другой job без прав (G3);
- запись только fast-forward от коммита, прочитанного в начале запуска.

**Ограничение писателя (р2).** Группа concurrency координирует только запуски одного workflow и не мешает другим способам записи. Поэтому **до включения обязателен ruleset для `state/queue`**:
- без удаления;
- без force-push;
- запись только для GitHub Actions этого репозитория (bypass list) или эквивалентное ограничение, доступное на текущем плане.

Это проверяется пробой: push с пользовательского аккаунта в `state/queue` должен быть отклонён. Если на текущем плане такое ограничение технически недоказуемо, этап 2 остаётся заблокированным. `main` ради этого не ослабляется.

**Конфликт fast-forward (р2).** Если push отклонён, потому что ветка ушла вперёд:
- запуск завершается с `RECOVERY_REQUIRED` (код 3);
- запись не повторяется, очередь не пересчитывается;
- выполненная работа не считается принятой;
- задача остаётся такой, какой её видит новый HEAD `state/queue`;
- следующий плановый запуск начинает с нового HEAD.

**Происхождение (р2).** Автор и сообщение коммита **не являются доказательством**: их может задать любой, кто может писать в ветку. Доказательство складывается из трёх частей:
1. ruleset, который не даёт писать в ветку никому, кроме Actions;
2. `STATE_MANIFEST.json` с `run_id`, `run_attempt`, `workflow_ref`, SHA кода из main, `QUEUE_VERSION`, sha256 очереди;
3. проверка при чтении через API: run `run_id` существует, его workflow — `autopoiesis-cycle.yml` этого репозитория, `head_sha` совпадает с манифестом, conclusion = success.

Если какая-то часть не сходится, исход `RECOVERY_REQUIRED`.

**Bootstrap (р2).** Только владелец, отдельный dispatch с явным вводом `bootstrap_state=true`:
- проверяет, что `state/queue` **не существует**; если ветка есть, отказ без записи;
- создаёт минимальную очередь (пустую или из `TASKS.json`) и манифест с run id bootstrap;
- плановый запуск никогда не создаёт и не сбрасывает ветку: без неё он даёт `RECOVERY_REQUIRED`.

**Миграция и восстановление (р2).** Если `QUEUE_VERSION` в ветке меньше версии кода:
- миграция — отдельный коммит в той же job: детерминированная функция того же вида, что `migrate_queue`;
- исходная версия остаётся в истории ветки, это и есть резервная копия;
- результат проверяется `load_queue`;
- при отказе миграции — `RECOVERY_REQUIRED`, без записи.

Версия в ветке **больше** версии кода (откат кода) — всегда `RECOVERY_REQUIRED`. Очередь никогда не сбрасывается молча.

## 4. G3: привязка DONE к проверенному коду

Детальный план реализации: `G3_IMPLEMENTATION_PLAN_2026-10-27.md`. Здесь контракт.

1. Проверяемый объект — коммит. В начале цикла фиксируются `commit_sha` и `tree_sha` (`git rev-parse <commit>^{tree}`).
2. Обработчик работает на извлечённом снимке этого коммита (`git archive`), а не на рабочем каталоге. Изменения рабочего каталога ни до, ни после теста на результат не влияют.
3. Запись PASS/FAIL содержит задачу, попытку, отпечаток аренды, `commit_sha`, `tree_sha`.
4. DONE принимается, только если последний PASS этой задачи в этой попытке под этой арендой имеет **те же** `commit_sha` и `tree_sha`. DONE записывает их с `revision_semantics = "tested_commit_tree"`.
5. Перед DONE координатор сверяет, что `tree_sha` — дерево `commit_sha` в объектах git. При несовпадении — `RECOVERY_REQUIRED`.
6. Старые доказательства сохраняют свою семантику (`tested_source_snapshot_sha256`, `migrated_v1_bound_pass_revision`) и **не повышаются**. Новые DONE со старой семантикой после миграции отклоняются.
7. (р2, по GPT) Пара `(commit_sha, tree_sha)` избыточна: дерево определяется коммитом. Обе записываются ради явности. Факт, что тесты выполнялись на этом снимке, доказывает не пара, а путь кода: снимок извлекается из `commit_sha` самим координатором и передаётся обработчику. Это проверяется тестом.

## 5. Доказательства для перехода к автономности

| Утверждение | Минимальное доказательство |
|---|---|
| «Цикл работает» (этап 1) | run на main: COMPLETED на реальной задаче; артефакт с commit SHA |
| «DONE означает проверенный код» (G3) | тесты из плана G3 на точном SHA + CI run |
| «Цикл продолжается без человека» (этап 2) | **два последовательных плановых запуска**; второй читает `state/queue`, записанную первым (оба run id, оба коммита состояния) |
| «Восстановление работает» | запуск, отменённый посреди выполнения, затем следующий: аренда снята по TTL, исход в истории |
| «Защита от гонки записи» | два одновременных запуска: один fast-forward, второй `RECOVERY_REQUIRED` без записи |
| «Только Actions пишет в состояние» | отклонённый push с пользовательского аккаунта |
| «Выключатель работает» | запуск с выключателем: `DISABLED`, SHA `state/queue` не изменился |

Без этих run id автономность не заявляется.
