**3. PASS/DONE привязаны к задаче, попытке, аренде, `commit_sha`, `tree_sha`; проверка на чистом снимке?** AGREE.
Уточнения:
- «Чистый checkout» реализуется как `git archive <commit>` во временный каталог. Он не зависит от состояния рабочего каталога и не содержит `.git`, поэтому обработчик не может сменить HEAD.
- Путей к DONE три (план G3 §0). Привязка обязательна для всех: путь через `run_tasks.py update_task_status` закрываем, проба в `ci.yml` переходит на commit/tree (нужно «да» владельца).

**4. Ограничения для `state/queue`.** Обязательны все, до включения:
1. ruleset: без удаления, без force-push, обновлять может только GitHub Actions (bypass), проверено отклонённым push с пользовательского аккаунта;
2. запись только fast-forward от коммита, прочитанного в начале запуска; при отказе `RECOVERY_REQUIRED` без повтора;
3. concurrency group на workflow цикла, без `cancel-in-progress`;
4. `STATE_MANIFEST.json` (run id, attempt, workflow ref, SHA кода, версия, sha256 очереди) плюс проверка run через API при чтении; автор и сообщение коммита доказательством не считаются;
5. SHA кода из манифеста — предок текущего main, иначе `RECOVERY_REQUIRED`;
6. версия очереди в ветке больше версии кода — `RECOVERY_REQUIRED`;
7. право `contents: write` только у job записи состояния; обработчик в другой job без прав.

**5. Обязательные правила bootstrap, миграции, recovery, kill switch.**
- Bootstrap: только владелец, явный dispatch, только если ветки нет; плановый запуск ветку не создаёт и не сбрасывает.
- Миграция: детерминированная, идемпотентная, без повышения доказательств; исходная версия сохраняется (`.vN.bak` локально, история ветки на этапе 2); при отказе ничего не пишется.
- Recovery: аренды с TTL; истечение на последней попытке — REJECTED; неоднозначность — `RECOVERY_REQUIRED` (код 3), никогда не пустая очередь.
- Kill switch: файл и переменная репозитория; `DISABLED` (код 0) без единой записи; выключатель проверяется **первым** шагом workflow (идея из #49 `64b4a45`).
