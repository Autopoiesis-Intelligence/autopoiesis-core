## 5. Предлагаемая минимальная архитектура (позиция Claude)

Принцип: в ядре только то, без чего нельзя доказать один полный цикл «проблема → принятое изменение». Остальное адаптеры.

**Авторитетное состояние одно: git main.**
- X = дерево файлов на SHA main. R = очередь задач и записи проверок, закоммиченные в main. Ψ на SHA = (дерево, очередь).
- Экземпляр = ветка, lineage = история коммитов, происхождение = SHA и id CI-запуска.
- Отдельная Ψ-машина, SQLite и модель экземпляров из Gnosis-Core не нужны: они дублировали бы git.

**Компоненты ядра:**

| Компонент | Состояние, которым владеет | Вход → выход | Инвариант | Почему в ядре |
|---|---|---|---|---|
| Очередь и жизненный цикл | `TASK_QUEUE.json` в main | кандидаты → статусы | закрытый граф переходов, история только дописывается | без неё нет памяти о задачах |
| Выбор | нет (чистая функция) | очередь → ≤1 задача | детерминированность при равной очереди | иначе селектор скрыт снаружи |
| Кандидат | нет | задача + base SHA → патч с digest | патч привязан к base SHA и не трогает workflow | граница между генератором и проверкой |
| Проверка | запись проверки | base SHA + патч → evidence (tree digest, результат тестов, run id) | evidence на другом SHA недействителен | без неё нет доказательства |
| Ворота | нет (чистая функция) | evidence + вердикт аудитора → допустим / нет | без вердикта на точном SHA не допустим | единственное место решения о допуске |
| Принятие | — | PR → слияние владельцем | только человек | вне ядра намеренно: это граница полномочий |

**Адаптеры (не ядро):** генераторы (шаблонный, Copilot), GitHub I/O, бюджет Copilot (`agent_budget.py`), claims (`coordination.py`), разбор вердиктов (`audit_verdict.py`), restore из артефактов.

**Отложить до первого доказанного цикла:** аренды и восстановление зависших задач (A9: при одном запуске за раз и состоянии только в main упавший запуск ничего не оставляет), рефлексию, память, предложения правил, эволюцию самой модели эволюции.

**Обязательное условие безопасности до подключения Copilot к циклу:** шаг, который исполняет сгенерированный код, работает в отдельном job с `permissions: contents: read` и без секретов. PR создаёт другой job, который получает только патч и evidence.

**Проверка осмысленности:** кандидат допустим, только если хотя бы один тест падает на base SHA и проходит с патчем, либо патч закрывает задачу с проверяемым критерием. Разница digest этого не доказывает.
