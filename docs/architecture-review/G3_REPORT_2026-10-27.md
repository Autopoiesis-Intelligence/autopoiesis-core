## 2. Контракт очереди v3 (`autopoesis/task_queue.py`)

- `QUEUE_VERSION = 3`.
- `VERIFICATION_RECORDED` может нести `commit_sha` и `tree_sha` (40 или 64 hex). Пара записывается только целиком.
- DONE требует последний PASS этой задачи в этой попытке под этой арендой с тем же `commit_sha` и `tree_sha`. DONE записывает пару и `revision_semantics = "tested_commit_tree"`.
- Параметр `revision` у `advance_task` убран. В PASS `revision` остаётся дополнительным доказательством, но DONE не разрешает.
- `legacy_history_length` — длина перенесённой при миграции истории. DONE со старой семантикой допустим только внутри неё. Отсутствие ключа означает 0.
- Повтор истории проверяет то же, что и `advance_task`, поэтому подделанный DONE в файле отклоняется при загрузке.

## 7. Что не доказано

1. **Изоляция прав обработчика.** Снимок ограничивает только то, какой код видит обработчик. Процесс обработчика по-прежнему может писать куда угодно, в том числе в рабочий каталог и файл очереди (тест 4 это делает намеренно). До содержательного обработчика нужна отдельная job без прав (E4).
2. **Подлинность самого файла очереди.** Привязка проверяется при повторе истории, но тот, кто может писать файл, может переписать и PASS, и DONE согласованно. Подписи или внешнего якоря нет. Граница `legacy_history_length` тоже не защищена от такой правки.
3. **`merge_candidates` сортирует историю по времени.** При сдвиге часов событие теоретически может переехать через границу legacy. Тогда загрузка откажет (fail-closed), но это не проверено тестом.
4. **Синтетическая проба в CI** получает DONE с `tested_commit_tree`, хотя никакой проверки коммита не было. Это помечено уровнем и текстом пробы, но семантика DONE для неё условна.
